# 1편 재현 검사 결과 (DESIGN.md 0절, 16절 2단계)

`python tutorial.py repro` — 원래 1편 코드(`record_ep1.py`, `build_ep1.py`)와 새 엔진(`scenario.yaml`)으로 1편을 각각 만들어 비교합니다.
같은 목소리 파일을 함께 씁니다. 결과는 `output/repro/repro.json`.

- 기존에 사용자에게 전달한 1편 최종 파일은 저장소에 없어서, "원래 코드로 지금 다시 만든 1편"을 기준으로 비교했습니다.
- 소요: 새 엔진 만들기 약 35분(녹화 1.5분, 본편 연출 10분, 인트로 4분·아웃트로 11분, 출력 3분).

## 주의: 기준 녹화는 같은 때 다시 찍는다 (2026-10-10)

목록 고르기(F8)처럼 조작이 문장보다 길게 걸리는 장면은 컴퓨터 빠르기만큼 밀린다. 같은 컴퓨터에서도 아침 기준 녹화는 F8 이 9.89초,
오후에 원래 코드로 다시 찍으면 10.21초, 새 엔진은 10.10초였다. 몇 시간 전 기준과 비교하면 엔진이 같아도 0.3초쯤 어긋나므로,
`python tutorial.py repro` 는 새 엔진 녹화와 원래 코드 녹화를 연달아 찍은 뒤 편집·비교한다. 검사 중에는 다른 무거운 작업을 돌리지 않는다.


## 판정 기준 바로잡음 (2026-10-10, 6단계 중)

원래 1편 코드끼리 30분 간격으로 두 번 찍어도 영상 시작부터 잰 시각이 0.56초 어긋났다(S3: 누른 뒤 가입 양식 화면이 뜰 때까지
기다림 → 사이트 로딩 속도, F8: 목록 5개 고르기가 문장보다 김 → 컴퓨터 빠르기). 한 장면에서 밀리면 뒤가 전부 밀리므로,
"영상 시작부터 0.25초 이내"는 엔진이 아니라 실시간 녹화의 흔들림을 재고 있었다. 그래서:

| 비교 | 기준 |
|---|---|
| 클릭·밝게 하기 위치 | 0px 에 가깝게(1.5px 이내) — 그대로 |
| 박자 | **장면마다 그 문장이 시작된 때부터 잰** 클릭·밝게 하기 시각 차이 0.25초 이내 |
| 밀림 | 영상 시작부터 잰 차이 — 보고만 함 |
| 같은 녹화 편집 | 자막·챕터·길이·프레임 픽셀까지 같음 — 그대로 |
| 전체 | 형식 같음, 길이·자막 시각은 밀림+0.1초(길이는 +0.3초) 이내, 챕터 이름 같고 시각은 밀림+1초 이내 |

결과: 장면 안 박자 차이 원래 코드↔새 엔진 0.17초(원래 코드끼리 0.19초), 밀림 0.42초, 같은 녹화 편집은 픽셀까지 같음 → **통과**.
